# Dungeon Quest Reborn Guide MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local, production-buildable Dungeon Quest Reborn wiki MVP with honest evidence states, 15 core routes, distinctive responsive UI, and complete technical SEO.

**Architecture:** Next.js App Router renders a typed content registry through shared server components; only search, menu, and copy interactions are client components. A single route/content source drives metadata, schema, sitemap, navigation, and search so that evidence and indexability rules cannot drift.

**Tech Stack:** Next.js, React, TypeScript, Tailwind CSS, Vitest, Testing Library, Fuse.js, Lucide React.

**Spec:** `docs/superpowers/specs/2026-09-02-dqr-mvp-design.md`

## Global Constraints

- All user-facing site content is English.
- Do not use official screenshots, logos, character art, fabricated codes, fabricated Trello/Discord status, or mockup values as facts.
- Use the exact final color tokens and Cinzel/Inter typography split.
- Routes below the content threshold receive `noindex, follow` and stay out of the sitemap.
- No ads, autoplay, tracking, accounts, market, calculator, or deployment are in scope.
- Preserve the supplied Markdown files and `mockups/final.html` unchanged.
